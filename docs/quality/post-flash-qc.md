# ESP32 燒錄後 QC 清單

依據：[專案協作規則](../../AGENTS.md)。主代理負責硬體操作與整合；QC（Ampere）獨立核對保存證據，回報 Gibbs（ESP32）、Kierkegaard（物理）及 Planck（資料）。本清單不建立常駐監控。

## 觸發與保護原則

1. **編譯成功、確認正確目標、完整寫入／校驗成功且燒錄工具正常返回後，同一流程立即喚回 QC。** 任一步失敗不得稱已部署。交付來源版本／公開來源 SHA256、建置設定、裝置識別、燒錄結果及證據位置；編譯與寫入成功分開記錄。
2. 先保存本次自然啟動訊息；錯過版本字串即標「待確認」，不得以原始碼／編譯文字冒充實板讀回，也不為補字串額外 reset、重燒或斷電。
3. 預設COM3由主代理唯一操作，QC判讀其保存證據；若主代理明確移交QC收集，其他代理人不得同時開埠，仍遵守同一操作界線。本輪由主代理收集、QC獨立判讀。操作者先被動確認IDLE且沒有校正收集；狀態未知、正在記錄／校正時停止額外探測、維持原狀。靜默不等於當機或IDLE。`STATUS`沒有獨立cal_mode欄，須搭配被動輸出、操作紀錄與現場回報。
4. 自動唯讀命令僅 `HELP`、`STATUS`、`WIFI STATUS`、`ADXL_DIAG`（大寫＋換行）。不循 HELP 自動執行其他命令；不送 STOP／CLEAR／UNCAL，不切 WiFi、不改距離／極性，不去皮、校正、ARM 或移動物件。唯讀輸出也占用時間，不能稱為對採樣零擾動。
5. 若已有 CAL_USER 或 DONE／FAULT 保留 trial，記錄實際狀態與歷程，**不得為符合「預期 UNCAL／IDLE」清除或重置**；先交主代理核對。DONE／FAULT 的 WiFi 暫停不是連線缺陷，狀態不適用的檢查標未測。
6. 不讀秘密檔或含憑證的建置產物；公開證據不含 SSID／密碼。保留原 capture，不覆寫歷史；來源與報告都留 SHA256。開埠設定與關埠由主代理紀錄，不由 QC 冒稱親自操作／目視／量測。

## 唯讀流程與驗收證據

主代理確認可查詢後，起始保存 STATUS 與 ADXL_DIAG，HELP、WIFI STATUS各一次，以約20秒被動STATUS作首輪基線；末端再各保存一次STATUS與ADXL_DIAG，記錄真實主機發送／接收時間，才能比對ACC_RX與DIAG_ERR等首末快取。每次新增查詢前確認狀態仍適用；缺某回應則記缺項，不無限重送。這是觀察窗，不是穩定性或精度門檻；主機時間也不是感測器精確取樣時間。舊capture若沒有逐筆時間戳，保留原行序與整窗時間，不補造發送時間。

| 檢核 | 明確預期與所需證據 | 結論限制／異常處理 |
|---|---|---|
| 來源、目標、燒錄 | 主代理提供本次公開來源雜湊、core／FQBN、埠及板／晶片識別、完整分區寫入或未變更區核對、Hash 校驗與正常返回紀錄 | 雜湊僅識別所列檔案；沒有來源至建置對應時標缺口，不推成實板映像雜湊。二手交接與原始燒錄輸出分列 |
| 版本／啟動 | 自然啟動 capture 的實板版本字串符合目標；保留 boot／reset 原文及前後時間 | STATUS 的 LAYOUT、距離或原始碼版本不足以唯一辨識實板版本；錯過啟動標待確認 |
| 狀態／設定 | 與本次操作歷程相符的 phase／reason、CAL、POL、DIST、腳位／版面、保留 trial；本版距離設定 220mm，初始 UNCAL／POL=-1/-1 只在確知剛重啟且未設定時作比較 | 距離讀回不證實幾何量測；既有校正或 trial 不為「復原預期」清掉 |
| WiFi／IP | IDLE 且非校正時，WIFI STATUS 有回應；本次要求連線則 CONNECTED、requested=1、radio=1、有效非零區網 IP；記行號及時間窗 | IP 不證外網；radio 是軟體標記。未授權掉線／ON／OFF 注入，重試與量測互斥標未測 |
| HX 更新 | 至少首末兩筆 STATUS：RAW 有效且非 ADC rail、HX=OK、RX 增加；AGE 搭配有效資料判讀，本版 1000ms 起判過期 | RAW 未變不一定停更；RX／AGE 較有依據。RAW=NA 時 AGE=0 不算新資料；不以 counts 冒充公克 |
| ADXL 更新 | 多筆 STATUS 的 ADXL=OK 支持本版「最近 1000ms 有讀到」；ADXL_DIAG 的 ACC_RX 記首末值及快取有效性 | 只有一次 ACC_RX 就不報更新差值／取樣率；MISSING 歷史不因短窗 OK 結案。不額外搖動感測器 |
| 錯誤／FIFO | 分別保留首末 ERR／AERR／FIFO_FULL 及差值；快取 FULL_OBS／DEPTH_OBS／OVR_OBS／DIAG_ERR、PRE／POST、INIT、EVENT、poll／OLED 耗時及有效旗標 | 累計非零須追蹤；單次診斷無法計 DIAG_ERR 增量。FIFO 未解或零增量都不能判動態完整；不清 FIFO／警示來「修好」 |
| 重啟跡象 | 觀察窗內有無重複 banner、reset 原因、計數回退、設定／連線突變，保留原文 | 回退可能是溢位／新輪次；沒看到重啟只描述本窗，不保證窗外未重啟 |
| OLED／RGB 目視 | 現場提供同版、同窗照片或具時間與觀察者的回報：八行可讀、無裁切，WiFi 圖示與連線狀態一致；RGB 實際熄滅 | OLED ACK、繪圖原始碼、SENDS、OFF_REQ 都不替代目視；QC 未親見須明列證據提供者，無證據即未測 |
| Tracker／校正／trial | 只讀現況，列出兩路電位、POL、距離、校正與 trial 保存狀態 | 本輪不驗觸發／高速精度、TARE／CAL／ARM／DUMP、radio 停止、落下或材料效果；未測不得填通過 |

## 三層判定及總結界線

| 層次 | 可由本流程支持 | 不能自動推論 |
|---|---|---|
| 軟體功能 | 指令回應、設定讀回、待機連線、近期資料及診斷呈現 | 主機測試／編譯／燒錄校驗不代替實板功能；靜態 OK、零交易錯誤不證動態 |
| 量測系統 | 如實列出校正、極性、FIFO／時序與動態驗證缺口 | UNCAL／POL 未確認時不具完整量測前提；缺校正不等於程式 bug。CAL_USER 也還須獨立驗證，不能套用歷史 RAM 比例 |
| 材料 | 本次一般不具材料驗收證據，列待補／未測 | 未完成量測系統、試片條件與重複試驗，不能比較材料優劣 |

總結必須寫適用範圍；以已觀察失敗優先於缺證，不能用「未測」掩蓋失敗：

- **通過**：宣告範圍內所有必查項有本次證據且符合預期，無未解關鍵警示；整份部署後 QC 尚缺實板版本、目視或關鍵診斷即不得全項通過。量測／材料另須各自驗收。
- **條件通過**：已證明限定功能可用，限制與後續工作明列且主代理接受用途限制，例如僅供 IDLE 連線／唯讀檢視。UNCAL／POL 未確認只能落在此等限定用途或待補；FIFO 未解不能被條件通過包裝成量測可用。
- **未通過**：本窗證據確定違反宣告用途的必要條件，例如目標／版本不符、應更新卻持續 MISSING／STALE、可確認的異常重啟、錯誤增加，或待驗收資料品質仍有未處理警示。標明違反的是哪一層，不直接指定根因。
- **待補**：不足以完成上述判定，例如沒留啟動版本、目視缺席、僅有單次快取、FIFO 警示待界定且尚未進入資料品質驗收。列出已通過子項與阻礙；目前 UNCAL／POL 未設及 FIFO 未解不得因此得到完整量測「通過」。

## 留存與四角色回報

每版報告至少包含：來源版本／公開來源 SHA256（與燒錄映像的對應限制）、目標、建置／燒錄依據、capture 類型（歷史／本輪新觀察）、命令／時區／時間窗／行號、預期／實際／結論、操作者與關埠、未測／限制、缺陷或待補 ID／嚴重度／負責人／重測條件。嚴重度按用途影響評定，證據缺口不冒充已確診軟體缺陷。

QC 交主代理後，由 Gibbs 處理軟體與 FIFO／更新診斷、Kierkegaard 核對校正／時序／量測界線、Planck 整理證據與版本一致性，主代理整合必要修訂。修訂後若再燒錄，立即以新 capture 重跑本流程；舊報告不能關閉新版問題。由主代理更新 handoff、回報埠與 Git 狀態；QC 不越權改其餘檔案。
