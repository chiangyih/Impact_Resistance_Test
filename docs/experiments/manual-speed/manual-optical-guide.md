## 一次測試的操作順序（本輪已匯出，未清除或重試）

1. 送`SPEED STATUS`核對手動模式及保存狀態；確認上述前提與目前沒有待保存結果。
2. 送`SPEED START`。預期顯示READY並進入WAIT_UP；此處沒有準備倒數，可從容準備，尚不計算通過時間。
3. 以**同一個反射標記**由上向下依序通過兩頭；不可用兩隻手分別觸發。不需要搬動或敲擊HX／ADXL。
4. 上方觸發後才計時；下方須在30秒內觸發，小於200µs的間隔作防錯。等待／計時期間不刷新OLED、不輪詢ADC，也不服務網路。
5. 完成後預期OLED顯示並保留DT／V；若主機監控已關，由主代理以DTR=off／RTS=off重新連線、不另行重置，再以`SPEED STATUS`核對結束狀態及`SPEED DUMP`保存原文與畫面讀值。關埠期間的MCU結果不會自動存到主機。
6. **先確認匯出已存檔，再送`SPEED CLEAR`，才能重試。** SPEED CLEAR只清手動模式結果，不清校正或原ARM trial；radio到此才解除手動暫停，恢復依待機策略處理，不保證立即連上。

若需取消，送`STOP`保留手動FAULT與原因，先`SPEED DUMP`保存，再`SPEED CLEAR`。無有效上→下時間差時，時間與速度填「待確認」或「無法定量＋原因」，不可填0或把FAULT當有效速度。

## 指令與保存規則

| 指令 | 本模式用途 |
|---|---|
| `SPEED START` | 在前提符合時進入READY／WAIT_UP，暫停radio |
| `SPEED STATUS` | 查手動狀態與結果；不是原ARM資料匯出 |
| `SPEED DUMP` | 匯出手動設定、狀態／原因與已有計時結果；主機另存原文 |
| `SPEED CLEAR` | 匯出保存後清手動結果並解除手動radio暫停，供下一輪使用 |
| `STOP` | 中止手動等待／計時，保留FAULT；不清既有校正或原ARM trial |

不要用原`ARM`啟動此模式，也不要以原`CLEAR`取代`SPEED CLEAR`。完成及FAULT保留期間WiFi仍暫停；資料留在RAM，斷電／重啟前須保存，指令回應不等於主機已成功寫檔。

## 數值與紀錄界線

距離220mm時：`v = 0.220 / Δt_s = 220 / Δt_ms` m/s。一般式為`v = distance_mm × 1000 / Δt_us` m/s；須有有效時間差才可代入，只代表兩點平均速度。

30秒是上方後的等待上限，200µs是過短間隔防錯；兩者均不是精度驗收門檻。裝置微秒計數與OLED小數位數不等於光學鏈準確度，電位確認也不代替延遲／抖動驗證。
